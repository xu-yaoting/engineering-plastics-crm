# CRM 内部试用一页说明

## 当前使用范围

- 仅限公司内部 2-3 人试用。
- 只在内网使用，不对公网开放。
- 可以录入真实业务数据。
- 遇到问题先记录，不要反复尝试同一个危险操作。

## 访问方式

- Nathan 先在主机 Mac 上运行内网启动脚本。
- 启动后会显示“同事访问”地址。
- 同事用浏览器打开类似下面的地址：

```text
http://192.168.1.12:5173
```

- 实际 IP 以启动脚本显示为准。
- 如果打不开，先确认同事和主机 Mac 在同一个 Wi-Fi 或内网。

## 使用前确认

- 打开 CRM 后，先确认页面能正常加载。
- 如果保存失败、页面报错、库存或金额异常，先停止当前操作并反馈。
- 不要直接改数据库文件。
- 不要把 CRM 链接发给试用范围外的人。

## 数据录入基本规则

### 公司

- 公司名称写完整正式名称。
- 不要把联系人姓名、备注、临时说明写进公司名称。
- 同一家公司不要重复建档，先搜索再新增。

### 联系人

- 尽量填写姓名、职位、部门、邮箱、电话。
- 邮箱未知就先留空或备注，不要随便填无意义符号。
- 联系偏好、语言、特殊情况写在备注里。

### 询盘

- 写清楚材料、规格、数量、应用场景、紧急程度。
- 不确定的信息写“待确认”，不要猜技术参数。

### 报价

- 发给客户前必须核对客户、联系人、产品、数量、单价、币种、总价、付款条款。
- PDF 需要预览确认后再使用。
- 草稿报价不等于正式报价。

### 订单

- 订单状态按真实进度更新。
- 不要为了“看起来快一点”提前改状态。

### 库存

- SKU 必须唯一。
- 新增产品前先搜索是否已有同规格产品。
- 入库、出库、调整都要写清楚数量、日期、操作人和原因。
- 库存调整只用于盘点或纠错，不用于正常出入库。

### 回款

- 录入前确认客户、发票/订单、金额、币种、日期。
- 不要录入超过剩余应收的金额，除非已经确认是预付款或特殊情况。

### 发货

- 发货前确认订单、客户、地址、物流方式和跟踪信息。
- 发货状态按真实物流进度更新。

## 删除和修改规则

- 真实业务数据不要随便删除。
- 普通文字错误可以直接修改。
- 库存、回款、订单金额相关错误，先反馈 Nathan，再决定怎么修。
- 严重错误需要记录问题编号。

## 问题优先级

### P0：马上停止并反馈

- 保存失败。
- 数据丢失。
- 金额错误。
- 库存数量错误。
- 客户、订单、回款、发货关联错了。
- CRM 无法打开。

### P1：本周内处理

- 流程卡住但数据没错。
- 缺少真实业务需要的字段。
- 搜索、筛选、报表影响工作效率。
- 报价 PDF 或邮件草稿有明显业务问题。

### P2：后面优化

- 排版、文字、按钮位置。
- 小体验优化。
- 不影响业务的显示问题。

## 反馈问题时请提供

- 哪个页面或模块。
- 做了什么操作。
- 期望结果。
- 实际结果。
- 是否影响客户、订单、库存、回款或发货数据。
- 截图或记录名称。

可按这个格式：

```text
日期：
反馈人：
模块：
优先级：P0 / P1 / P2
问题：
操作步骤：
是否影响数据：
截图或记录：
```

## 每天下班前

- 保存当天所有需要保存的数据。
- 把发现的问题记录下来。
- Nathan 或指定负责人做一次数据库备份。

## 当前不要做

- 不要批量导入大量数据，除非已备份。
- 不要让更多同事同时试用，先稳定 2-3 人流程。
- 不要把系统暴露到公网。
- 不要绕过 CRM 直接改数据库。
